# Дни работы трамваев и оценка активности за 2025 год

Сетка охватывает 365 дней и маршруты 1, 5, 7, 11, 12, 17, 25, 26, 28, 50. **Это не полный архив расписаний.** Полных маршрутных суток с обоими направлениями найдено 0; частично подтверждены одни сутки — маршрут 7, 29 июля, направление 0. Остальные строки содержат доступные справочные интервалы и отдельную оценку по валидациям. Поиск выполнен 26 сентября 2026 года.

## Файлы

| `hourly_fleet_2025.csv` | 87600 строк: час × маршрут, оценка вагонов, прямые наблюдения, прежний часовой счётчик, объём выборки |

| `summary.json` | Покрытие, сравнение старого и нового расчёта, SHA-256 итоговых CSV |
| `sources/` | Сохранённые PDF, сжатый HTML и результат поиска по архиву |

CSV: UTF-8 с BOM, разделитель — запятая. Пустая числовая ячейка означает неизвестное значение. Ноль в наблюдаемой активности означает отсутствие пригодных отметок, **не подтверждённое отсутствие трамваев**. Идентификаторы пассажиров, валидаторов и отдельных вагонов в датасет не включены.

## Два разных расчёта

**Справочный ориентир по интервалу** (`fleet_reference_*`) равен:

`N = (длина двух направлений, км × 60 / скорость, км/ч) / интервал, мин`.

Длина берётся из датированной географии OSM проекта. Центральная скорость 16 км/ч, границы 14–20 км/ч — **допущения для анализа чувствительности**, а не сведения о скорости этих маршрутов. Отстой на конечных и резерв не включены. Нижняя оценка использует большую скорость и больший интервал; верхняя — меньшую скорость и меньший интервал. Это не доверительный интервал. При неполной геометрии или известном временном изменении значение пустое. **Этот ориентир не используется как знаменатель нагрузки на карте.**

**Оценка активности по валидациям** (`*_activity_estimate`, `mean_active_vehicles_estimate`) используется приложением. Старый счётчик считал каждый замеченный за час вагон целым вагоно-часом, даже если его сменил другой. Новый расчёт считает уникальные бортовые номера в каждом 5-минутном интервале и усредняет 12 интервалов. Короткие промежутки между отметками одного вагона заполняются, если расстояние между началами интервалов не превышает 20 минут и нет отметок этого вагона на другом маршруте внутри промежутка. Это предположение о непрерывном присутствии, не наблюдение. До первой отметки, после последней, через полночь и через большие разрывы активность не продлевается.

Прямой счётчик без заполнения (`direct_*`) и старый часовой счётчик (`old_*`) сохранены для сравнения. Найдено 26233 сочетания «вагон × 5 минут» с отметками на нескольких маршрутах; они могут отражать смену маршрута внутри интервала или ошибки источника. Они не скрыты, но по ним нельзя утверждать одновременное присутствие на нескольких маршрутах.

Январь–октябрь рассчитаны по исходным событиям. Ноябрь–декабрь — медианный профиль по восьми предшествующим неделям, доступным на 01.11.2025 00:00 МСК, без использования будущих событий. Минимум три пригодных наблюдения часа. В профиле рабочая суббота сравнивается с пятницей, праздник — с воскресеньем: это явное допущение, требующее проверки по календарю перевозчика. Неизвестный выпуск маршруту 5 не выдумывается.

`vehicle_hours_activity_estimate` — сумма почасовых оценок; `fleet_mean_24h_activity_estimate` — эта сумма / 24, включая ночь; `fleet_peak_hour_activity_estimate` — максимум часовых средних, не мгновенный пик. Для выбранного окна нагрузка вычисляется как сумма валидаций / сумма вагоно-часов. Деление на ноль или неизвестный знаменатель не производится. `identifier_coverage` показывает долю событий с пригодным номером, а не долю учтённых вагонов реального выпуска.

По маршрутам с наблюдениями новый итог вагоно-часов на 10–19% ниже старого. Это изменение метода, **не доказанное улучшение точности на 10–19%**. Для проверки точности нужны диспетчерские наряды/выпуск, расписания с оборотами вагонов либо GPS за 2025 год. Вагоны без отметок по-прежнему могут теряться; частота валидаций влияет на оценку.

## Воспроизведение

Из корня репозитория, после установки backend и подготовки истории/географии:

```bash
backend/.venv/bin/python backend/scripts/fetch_schedule_sources.py
backend/.venv/bin/python backend/scripts/build_fleet_activity.py
backend/.venv/bin/python backend/scripts/build_daily_service.py
backend/.venv/bin/moscowt --state-dir artifacts --dataset-dir dataset prepare-fleet
```

Повторное чтение сырых 62,4 млн строк нужно только при изменении исходных CSV или алгоритма активности. Для готового `observed-activity.json` второй шаг можно пропустить. Скрипт скачивания проверяет закреплённые SHA-256 (для сжатого HTML — распакованные байты, независимо от версии gzip); смена содержимого источника требует проверки, а не молчаливого обновления. Генератор дневного датасета сверяет прежние часовые счётчики, число событий и SHA-256 исходных файлов с предыдущим расчётом. Публикация создаёт новый неизменяемый `fleetId`; исходные суммы валидаций и прогноз пассажиропотока не меняются.

Чтобы заполнить пробелы, нужен архив расписаний с периодами действия, календарём исключений и обоими направлениями. При наличии связи рейс → наряд/вагон можно будет считать пересекающиеся во времени интервалы работы вагонов и заменить оценку по валидациям.
