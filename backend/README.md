# Backend «Потока»

Python 3.12; FastAPI/Pydantic, pandas/PyArrow, CatBoost/LightGBM/RandomForest. Версии библиотек закреплены в `uv.lock`. HTTP обслуживает сохранённые результаты; подготовка признаков и обучение выполняются в worker.

## Локальный запуск

```bash
uv sync --frozen --extra models --python 3.12
uv run moscowt serve --host 127.0.0.1 --port 8000
uv run moscowt worker --channel general
uv run moscowt worker --channel model
```

Последние три команды запускаются в отдельных терминалах. `MOSCOWT_WORKER_ENABLED=false` отключает только встроенный старый worker v1; при работе через отдельные процессы задайте эту переменную. Надёжнее использовать [Compose](../compose.yaml), где конфигурация уже задана.

С нуля, при наличии исходников пользователя:

```bash
uv run moscowt demo-prepare --weather-dir ../../weather_dataset --schedule /home/trias/Downloads/moscow_tram_schedules.csv
```

Команда создаёт версии январь–август без № 17 → сентябрь → история № 17 → октябрь, обучает три адаптера, публикует ансамбль и подключает ранее подготовленные оценки вагонов. `--quick` уменьшает число деревьев для проверки работоспособности; такие результаты не заменяют полный рецепт.

Общие параметры `--state-dir`, `--dataset-dir`, `--data-root`, `--source-dir` передаются **перед** подкомандой. По умолчанию пути абсолютны относительно репозитория: `artifacts/`, `dataset/`, `artifacts-data/`, соседний `../dataset/`. CLI `train/backtest/forecast/bootstrap/submission` сохранён как прежний конкурсный профиль; новые импорт/обучение/сценарии используют `/api/v2`.

```bash
uv run moscowt bundle
uv run moscowt --state-dir /tmp/restore-state --data-root /tmp/restore-data restore /path/to/bundle.tar.gz
uv run moscowt openapi > openapi.json
```

Восстановление допускается только в пустые каталоги. Архив включает checksum/размер каждого файла, все версии канонических данных, описания маршрутов и их версии, модели, выпуски, географию, расписания, источники и сценарии. SQLite заново строится из manifest; текущие задания и незавершённые загрузки не переносятся. Pickle/joblib произвольного пользователя не принимаются через HTTP; модельные архивы предназначены для доверенного локального восстановления.

## Границы модулей

| Слой | Модули | Ответственность |
|---|---|---|
| Приём | `data/normalization.py`, `data/repository.py` | Потоковое чтение CSV, проверка, preview/apply, полнота, Parquet по месяцам |
| Каталог | `data/catalog.py`, `storage.py` | SQLite WAL, версии маршрутов, checksum, CAS публикации, неизменяемые файлы |
| Признаки | `modeling/features.py`, `external.py`, `service_calendar.py` | Фиксированный origin, календарь, климатология и известные события, сохранённые погодные выпуски |
| География | `network_history.py`, `route_imports.py`, `spatial.py` | Версии OSM/CSV, сценарные посадки и пересечения участков |
| Модели | `modeling/contracts.py`, `adapters.py`, `service.py` | Общий контракт, обучение/прогноз, сохранение/загрузка, паспорт и применимость |
| Выпуск/агрегация | `publication.py`, `analytics.py`, `platform_exports.py` | Связь v1/v2 с одним dataset_id, строгие суммы, CSV/Parquet/конкурсный профиль |
| Выпуск вагонов | `schedules.py`, `fleet.py` | Выходы, интервалы физического вагона, конфликты, вагоно-часы и оценки по расписанию |
| Сценарии | `scenarios.py` | Независимые ID, множители, бюджет часов, сохранение исходного выпуска |
| Задания | `tasks.py`, `platform_worker.py` | Очередь, идемпотентность, lease, отмена, изоляция дочернего процесса |
| Интерфейс | `api.py`, `platform_api.py`, `cli.py` | Проверка HTTP-запросов и оркестрация, без обучения в HTTP |

Репозитории, провайдер погоды, адаптеры и расчётные сервисы имеют явные обязанности и используют композицию. Общий абстрактный класс нужен только заменяемым моделям; математические преобразования остаются функциями. Старые `forecasting.py`, `jobs.py`, `worker.py`, `exports.py` сохранены для действующих v1/конкурсных команд, а не как второй основной источник данных.

## Форматы импорта

Labels: UTF-8, `;`, `route;date;hour;boardings`, дата YYYY-MM-DD, час 0…23, целое неотрицательное значение. Ключ маршрут×час уникален. Raw: `ngpt_route;tran_date_time;validation_result;bus_exit_no;garage_number` (прочие столбцы допускаются); успех — `validation_result=1`. Неизвестное наблюдение остаётся `null`; `complete=true` означает утверждение полноты **выбранного источника**, а не всего пассажиропотока.

Режим `append` не перезаписывает известное значение и отклоняет конфликт. `upsert` исправляет известные строки новой версией, пропусками не стирает старые факты. `replace` полностью заменяет явный набор маршрутов и часов. Preview привязан к базовой версии; при конкурентном изменении apply отклоняется. Исходники хранятся под SHA-256. Полное повторение файла/спецификации не меняет текущие суммы; исправление создаёт новый ID. Автоматического удаления старых версий нет.

Полные назначения: `route;service_date;grafic;trip_num;direction;start;end;garage_number`. Пример ночного интервала: `23:30;25:30`. Физический вагон учитывается один раз по `garage_number`; пара маршрут+служебная дата+график определяет выход. `bus_exit_no` сопоставляется с графиком в пределах фактического времени, включая предыдущую служебную дату после полуночи. Повтор строки удаляется, несовместимые назначения дают конфликт.

Остановочное расписание пользователя определяется по заголовкам. Порядок записей одинаковых остановок используется для оценки рейсов; это допущение сохраняется в manifest. В сентябрьском CSV 2026 нет номеров вагонов/выходов, поэтому считать его точным выпуском нельзя. Неполные направления, пропущенные времена и неприменимый период дают явные предупреждения/неизвестный знаменатель. `schedule_scenario=true` разрешает перенос недельного профиля на другой период.

## Надёжность и ограничения

В `/data/shared`: `catalog.sqlite3`, исходники, месячные Parquet, расписания и внешние источники. В `/data/state`: модели, выпуски, снимки, сценарии, экспорты и очередь. У задания отдельный владелец и 30-секундный lease; после падения процесс забирает просроченное задание снова, максимум три попытки. Отмена завершает дочерний процесс. Файлы записываются через временный путь, fsync и atomic rename; manifest публикуется последним. Обучение не переключает опубликованную карту автоматически.

Один worker на канал удерживает файловую блокировку. Публикация снимка поддерживает `expected_snapshot_id`, устаревшая запись отклоняется. Кэши учитывают immutable ID, периоды, маршруты и сценарий. Числовая карта имеет ограниченный LRU; геометрия/OD-профили и нормализованные расписания также кэшируются. API/worker рассчитаны на один хост; SQLite не объявляется распределённой очередью.

Для малых произвольных наборов маршрутов модель достаточна, но миллионные запросы требуют ограничений: один импорт/выгрузка — до 5 млн маршрутно-часовых ключей; маршрутный запрос v1 — до 1464 интервалов; модель — максимум 366 дней, ансамбль и сезонная модель — 62 дня. Число потоков обучения ограничено `MOSCOWT_MODEL_THREADS` (по умолчанию 2). Погодный API вызывается только отдельным заданием и может быть недоступен; сохранённые выпуски и демо продолжают работать.
