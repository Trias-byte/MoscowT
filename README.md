# Поток

Веб-приложение для анализа и прогноза успешных валидаций московского трамвая. Включает карту маршрутов, историю за январь–октябрь 2025 года, готовые модели, сценарии движения, пассажирскую аналитику и экспорт CSV/Parquet.

## Запуск

Нужны Docker Engine и Docker Compose. Из корня проекта:

```bash
docker compose up -d --build --wait
```

- Приложение: <http://localhost:8080>.
- Документация API: <http://localhost:8080/docs>.
- Готовность: <http://localhost:8080/health/ready>.

Если сборщик на Linux не разрешает адреса реестров (`EAI_AGAIN`), выполните ту же команду с `MOSCOWT_BUILD_NETWORK=host`. Этот параметр относится только к сборке.

Для другого порта задайте `MOSCOWT_PORT=8082` в `.env` по образцу `.env.example`.

При первой сборке Docker скачивает базовые образы и программные зависимости. **Все данные, веса моделей, шрифты и схема трамвайных путей включены в проект.** После сборки обычная работа приложения не требует интернета, соседних каталогов или дополнительной загрузки датасетов. Обновление внешних погодных данных запускается отдельно по запросу пользователя и требует сети.

Первый старт восстанавливает комплект из `deliverables/` в именованные тома. Повторный старт использует сохранённые данные; пользовательские версии и публикации остаются в томах. Контрольные суммы поставки проверяются при сборке.

```bash
docker compose logs --tail=100 service
docker compose restart
docker compose down
```

`down` сохраняет тома; `down -v` удаляет историю, загруженные данные, модели и задания. Для перехода со старой конфигурации после резервного экспорта используйте `docker compose up -d --build --wait --remove-orphans`.

## Устройство поставки

По умолчанию один контейнер запускает API и два worker-процесса: для данных/экспорта и моделей. Общие ограничения: 4 CPU и 4 ГиБ памяти без дополнительного swap. При завершении дочернего процесса supervisor останавливает остальные; Docker перезапускает контейнер. SQLite и файлы результатов хранятся в томах `state` и `shared`.

При необходимости процессы можно разделить:

```bash
docker compose -f compose.workers.yaml up -d --build --wait
```

Конфигурации используют одинаковые тома и не предназначены для одновременного запуска под одним именем проекта. При переключении сначала остановите текущую конфигурацию командой `down` без `-v`.

| Каталог | Назначение |
|---|---|
| `backend/src/moscowt/` | API, доменные сервисы, репозитории, очередь и модели |
| `backend/src/moscowt/constants/` | Серверные константы по предметным областям |
| `frontend/src/` | React-интерфейс, контракты Zod, HTTP-клиент |
| `frontend/src/constants/` | Настройки, подписи, шкалы и константы интерфейса |
| `frontend/public/assets/` | Локальные шрифты, карта, Swagger UI и лицензии |
| `deliverables/` | Проверяемые архивы данных, моделей и конкурсный шаблон |
| `dataset/` | Компактные исходники и производные данные для подготовки и тестов |
| `scripts/` | Проверка целостности и обслуживание поставки |
| `backend/tests/`, `frontend/tests/` | Серверные, модульные и браузерные проверки |
| `ML/` | Отдельные исследовательские материалы; в Docker не входят |

## Работа с данными

В разделе «Данные и модели» доступны импорт истории, обучение, перенос моделей и публикация прогнозов. Задания сохраняются на сервере. В разделе «Сценарии» можно изменить погоду, расписание, сезонный коэффициент и ограничения движения. Карта и экспорт читают завершённый результат выбранного выпуска.

Основная поставляемая модель — ансамбль пяти CatBoost на горизонт 61 день. Сервис также поддерживает сезонную модель, ансамбль CatBoost/LightGBM/RandomForest и годовой сценарий. Новые прогнозы не получают автоматически качество исходной конкурсной модели.

Успешная валидация не равна уникальному пассажиру или числу людей в салоне. Значения на участках — модельные оценки. Пропуски истории не заменяются нулями. Пассажирские категории описывают билеты; когорты и инфраструктура имеют собственные фиксированные периоды.

## Разработка и проверка

Для локальной разработки нужны Python 3.12, uv и Node.js 22:

```bash
uv sync --directory backend --frozen --extra models
npm ci --prefix frontend
python3 scripts/verify_release.py --assemble deliverables/platform-demo.tar.gz
backend/.venv/bin/moscowt restore deliverables/platform-demo.tar.gz
MOSCOWT_WORKER_ENABLED=false backend/.venv/bin/python -m moscowt.standalone
```

В отдельном терминале: `npm run dev --prefix frontend`. Интерфейс разработки доступен на <http://localhost:5173>; Vite направляет API на порт 8000. Для `/docs` при локальной разработке сначала выполните `npm run build --prefix frontend`.

```bash
make check
make test
PLAYWRIGHT_BASE_URL=http://127.0.0.1:8080 npm run test:e2e --prefix frontend
```

Браузерным тестам нужен Chromium: `cd frontend && npx playwright install chromium`. Это инструмент разработки, в контейнере приложения он не требуется. Браузерные тесты создают данные и задания; запускайте их на отдельном тестовом экземпляре.
