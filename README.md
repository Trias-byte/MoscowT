# MoscowT · Поток

Локальная платформа анализа и прогнозирования **успешных валидаций по маршруту и московскому календарному часу**. Backend Python/FastAPI, frontend React/TypeScript, MapLibre и ECharts. Реализован P0 требований v2.

## Быстрый запуск

В поставке уже есть подготовленные данные, модель и прогноз. Нужны Docker и Compose:

```bash
mkdir -p artifacts
tar -xzf deliverables/artifacts.tar.gz -C artifacts
docker compose build
docker compose run --rm app prepare-network
docker compose up -d --no-build
```

Приложение: <http://localhost:8080>. OpenAPI: <http://localhost:8080/docs>. Порт доступен только на localhost. Контейнер ограничен **2 vCPU / 2 ГБ**; SQLite и артефакты сохраняются в `artifacts/`. Исходные файлы подключаются из `dataset/` только для чтения.

Если порт занят, задайте `MOSCOWT_PORT=8081` в корневом `.env` (пример — `.env.example`). В текущем рабочем окружении приложение запущено на <http://localhost:8081>.

Если стандартная сеть Docker на вашей машине не разрешает DNS:

```bash
docker build --network=host -t moscowt:p0 .
docker compose up -d --no-build
```

Для конкурсного экспорта в интерфейсе или CLI нужен исходный `dataset/test_submission.csv`: используется только порядок его ключей. Готовый результат включён в [`deliverables/submission.csv`](deliverables/submission.csv).

## Подготовка с нуля

Положите оригинальные labels, шаблон и справочник в `dataset/`, сохранив структуру архива. Для оценки числа вагонов используется подготовленный `dataset/derived/fleet/observed-activity.json`. Если его нет или изменились сырые данные, сначала выполните из корня репозитория `backend/.venv/bin/python backend/scripts/build_fleet_activity.py`: скрипт один раз прочитает `train.csv` и `test.csv`. Сырые CSV не нужны HTTP-серверу.

```bash
docker compose build
docker compose run --rm app bootstrap
docker compose up -d
```

`bootstrap` последовательно проверяет labels, подключает почасовую оценку вагонов, импортирует сеть, сравнивает два эксперта на ранних срезах, проверяет выбранный подход на сентябре–октябре, обучает финальную модель и выпускает ноябрь–декабрь. Подготовка не запускается при каждом старте HTTP-сервера. Для добавления оценки вагонов к существующей модели достаточно `moscowt prepare-fleet`; история и прогноз при этом не меняются.

Локальная разработка:

```bash
cd backend
uv sync --frozen --python 3.12
uv run moscowt bootstrap
uv run moscowt serve
```

В другом терминале:

```bash
cd frontend
npm ci
npm run dev
```

Vite доступен на `http://localhost:5173`, запросы `/api` проксируются на `127.0.0.1:8000`. Реальный API включён по умолчанию. Явная демонстрация: `VITE_DEMO=true npm run dev`.

## Что поставлено

- Полная история: **72 960 ключей**, 57 551 положительный ключ, 15 409 восстановленных нулей, сумма **59 667 191**.
- Независимый реестр маршрутов: **1, 5, 7, 11, 12, 17, 25, 26, 28, 50**. № 5 сохранён с явной политикой нулевого прогноза при отсутствии положительной истории.
- Неизменяемые снимки, Parquet, манифесты входов, модельные артефакты и атомарная публикация.
- Сезонный эксперт и календарная CatBoost-модель. Выбор по общему WAPE ранних 61-дневных срезов; сентябрь–октябрь не используется для повторной настройки выбранного решения.
- Маршрутная карта, временные ряды, историческое среднее, сравнение, матрица маршрут × время, таблица, пользовательский CSV и отдельный полный submission.
- SQLite-очередь экспорта, идемпотентность, восстановление заданий после прерывания worker, health endpoints и Prometheus metrics.

Выбран **сезонный эксперт**. Контроль сентября–октября: **WAPE 0,2324161995**, score **0,7675838005**. Это ретроспективная проверка по времени событий, а не результат на скрытом эталоне ноября–декабря. Подробности: [`deliverables/backtest.json`](deliverables/backtest.json).

## Смысл данных и ограничения

Одна успешная валидация — строка предоставленной выгрузки с успешным результатом. Она не доказывает число всех фактических посадок, людей на остановке или наполнение вагона. API публикует только `successful_validations`, `metricScope=route`.

Карта использует архив трамвайных путей и остановок OpenStreetMap **за 2025 год**. Версия выбирается по дате календаря: выбор дня меняет не только числа, но и трассы. Срезы загружаются на даты правок отношений маршрутов OSM; внутри периода используется последний срез. Подписаны выбранная дата и дата исходной версии. № 5 скрыт до официального открытия 16 декабря 2025 года. Геометрия 2026 года больше не используется для просмотра 2025 года. [Источники, лицензия и ограничения архива](dataset/geography/README.md).

Даты правок OSM не гарантируют фактические даты всех изменений движения. В частности, временные закрытия могут отсутствовать в OSM; архив не объявляется полным диспетчерским расписанием. При разрыве путей направление скрывается, а маршрут остаётся в числовых данных. Современная подложка OSM служит ориентиром; архивными являются трассы и остановки.

Кнопка **«Загрузить маршрут»** открывает отдельный импорт CSV с предварительной проверкой. Можно скачать шаблон или текущую трассу для изменения. CSV задаёт точки трассы, остановки, направление и период `[valid_from, valid_to)`. Для существующего номера заменяются только указанные направления и дни; после окончания возвращается исходная версия. Новый номер добавляется только на карту без выдуманных чисел. Импорт сохраняется в `artifacts/` и переживает перезапуск. [Формат CSV](docs/ROUTE_CSV.md).

Геометрические фильтры не меняют маршрутную сумму и не перенормируют оценки участков. Загрузка CSV меняет географию и геометрическую основу сценария участков, но не переобучает маршрутную модель и не создаёт числовые данные для нового номера. Направления представлены раздельно, со стрелками; нажатие на линию открывает карточку перегона.

Нули восстанавливаются только в проверенном историческом окне `[2025-01-01, 2025-11-01)`. Отсутствие будущего факта — `null`. Ноль № 50 21 сентября и спад 20 сентября сохраняются с флагом проверки. Полнота самой выгрузки не доказана.

Календарь интерфейса охватывает весь 2025 год: выбирается одна дата без диапазона. По умолчанию показан весь день (00:00–24:00 МСК); также доступны час и 12 часов с выбором начала. Карта, карточка, сравнение и таблица суммируют выбранные часы, график и тепловая матрица показывают день по часам. Слайдер всегда доступен: движение из режима «Весь день» выбирает отдельный час, а в режиме «12 часов» меняет начало интервала. Старые URL больше не привязывают выбранный день к ноябрю. Источник выбирается автоматически для каждого маршрута и часа: фактическое значение при наличии, иначе доступный прогноз. Январь–октябрь показывают историю, ноябрь–декабрь — прогноз. Подписи и пользовательский CSV различают источники. CSV содержит почасовые строки выбранного интервала. Если отсутствуют и факт, и прогноз, значение остаётся `null`.

Цветовая шкала карты учитывает оценку числа вагонов: границы **5 / 20 / 40 / 70 на вагон в час**, от светло-зелёного до пикового красного. Жёлтый начинается с 40, красный — с 70; границы заданы пользователем. Цвет рассчитывается отдельно для перегона и направления по предварительной модели, а не одинаково для всего маршрута. Модельные оценки не являются фактическим остановочным пассажиропотоком. [Допущения и ограничения модели участков](docs/SECTION_MODEL.md). Оценка вагонов — средняя активность в 5-минутных интервалах по `garage_number`, с заполнением коротких разрывов до 20 минут при отсутствии отметок на другом маршруте. Несколько валидаторов одного вагона не увеличивают счётчик. Для прогноза используется медиана сопоставимых часов за восемь предшествующих недель, минимум три наблюдения. Производственный календарь применяется как допущение: рабочая суббота сопоставляется с пятницей, праздник — с воскресеньем. Полный архив расписаний перевозчика не найден. [Датасет на каждый день 2025 года и ограничения источников](dataset/derived/schedules-2025/README.md) содержит отдельные справочные интервалы; они не подменяют знаменатель карты.

Для 12 часов и дня маршрутная интенсивность равна сумме валидаций, делённой на сумму почасовых оценок вагонов (вагоно-часы). Оценка перегона также агрегирует почасовые модельные потоки и вагоно-часы направления до деления. Шкала остаётся фиксированной; средние почасовые отношения не усредняются. Карточка, таблица и пользовательский CSV показывают число вагонов и интенсивность; `fleetId` связывает результат с неизменяемым артефактом. Серый означает отсутствие данных для расчёта, а не низкую нагрузку. Вагоны без событий могут быть пропущены; это предварительная оценка, не точный выпуск и не наполнение салона. Методика и контрольные суммы — в [описании оценки вагонов](dataset/derived/fleet/README.md). Конкурсный прогноз и его CSV не изменяются.

P1 отложен: полный raw-аудит, эмулятор, приём событий, replay, SSE и внешние признаки. Годовой прогноз, остановочные показатели, вместимость и интервалы неопределённости не объявлены доступными. Отчёт прежнего raw-аудита указан как внешний результат, не как повторно выполненная проверка P0.

Один API-процесс и один worker работают с общим локальным томом. Несколько реплик с этой SQLite-конфигурацией не поддерживаются. CLI-подготовку запускают последовательно; уже открытый снимок остаётся неизменным. Тайлы подложки могут требовать интернет, их отсутствие не блокирует схему, таблицы и экспорт.

## Проверки и документация

Пройдены 46 backend-тестов, 16 frontend unit-тестов и 15 Playwright-сценариев с изолированным каталогом состояния, TypeScript и production build. Проверены 21 архивный срез 2025 года, выбор версии по активному дню, дата открытия № 5 и полный цикл импорта CSV с сохранением и границами периода. Проверены геометрия по исходным путям OSM, названия и порядок остановок, январские данные, переход между историей и прогнозом, суммы за 12 и 24 часа, старые ссылки и происхождение строк CSV. Ранее на 2 vCPU / 2 ГБ измерено 300 RPS: p95 4,6 мс с прогретым кэшем и 148,3 мс с холодным, без ошибок, с параллельным экспортом. Проверено восстановление задания после SIGKILL worker и сохранность CSV после перезапуска контейнера.

```bash
cd backend
uv run pytest -q
uv run ruff check src tests scripts
cd ../frontend
npm test
npm run typecheck
npm run build
npx playwright install chromium
npm run test:e2e
```

E2E используют реальный подготовленный backend; перед ними выполните `bootstrap` или распакуйте поставленные артефакты. Снимки desktop/mobile сохраняются в `frontend/test-results/`.

Для проверки собранного контейнера: `PLAYWRIGHT_BASE_URL=http://127.0.0.1:8081 npm run test:e2e` из `frontend/`.
