# Поток · прогноз успешных валидаций московского трамвая

Запускаемый сервис с версионированием данных, обучением, прогнозом на день/месяц и годовым сценарием, картой, отдельной панелью сценариев и выгрузкой. Температура, влажность и осадки поступают в погодный ансамбль; ДТП и расписание изменяют доступное движение по явно указанному методу. Основной показатель — **успешные валидации**. Числа на остановках и участках — сценарные оценки; людей в салоне они не измеряют.

## Запуск готовой поставки

Запустите из корня репозитория и дождитесь готовности сервиса:

```bash
docker compose -f compose.single.yaml up -d --build --wait --remove-orphans
```

При переходе с прежнего `compose.yaml` эта команда заменяет три контейнера одним и сохраняет те же тома `moscowt_state` и `moscowt_shared`.

**Интерфейс приложения: [http://localhost:8080](http://localhost:8080).**

| Что открыть | Адрес по умолчанию |
|---|---|
| Карта и панель «Данные и модели» | [localhost:8080](http://localhost:8080) |
| Документация API (Swagger) | [localhost:8080/docs](http://localhost:8080/docs) |
| Проверка готовности | [localhost:8080/health/ready](http://localhost:8080/health/ready) |

Frontend и API доступны на одном порту **8080**. В `compose.single.yaml` он проброшен на внутренний порт контейнера `8000`. Приложение доступно с компьютера, на котором запущен Docker.

Чтобы использовать другой порт, например **8082**:

```bash
MOSCOWT_PORT=8082 docker compose -f compose.single.yaml up -d --build --wait --remove-orphans
```

После этой команды открывайте **[http://localhost:8082](http://localhost:8082)**; Swagger и проверка готовности также будут на 8082. Выбранный порт можно сохранить строкой `MOSCOWT_PORT=8082` в `.env`. Без переопределения используется 8080. Узнать фактический адрес уже запущенного контейнера:

```bash
docker compose -f compose.single.yaml port service 8000
```

### Если загрузка зависимостей прерывается

Если `npm ci` завершился с `EIDLETIMEOUT` при обращении к `registry.npmjs.org`, повторите сборку: скачанные пакеты сохраняются в BuildKit-кэше. Установка использует пять повторных попыток сетевых запросов, до пяти соединений и `--no-audit`; версии и проверки целостности остаются из `package-lock.json`. Обновление npm из уведомления не требуется. Audit можно выполнить отдельно командой `npm audit` в `frontend`.

Если registry доступен на Linux-хосте, но запросы из сети сборщика зависают, используйте сеть хоста **только на этапе сборки**:

```bash
MOSCOWT_BUILD_NETWORK=host docker compose up -d --build
```

При занятом порте добавьте `MOSCOWT_PORT=8082` перед командой. Рабочие контейнеры сохраняют обычную изоляцию сети и привязку API к localhost. Не удаляйте кэш или тома для исправления сетевого тайм-аута. Параметры: [npm fetch-retries](https://docs.npmjs.com/cli/v10/using-npm/config/#fetch-retries), [кэш BuildKit](https://docs.docker.com/build/cache/optimize/#use-cache-mounts), [сеть сборки Compose](https://docs.docker.com/reference/compose-file/build/#network).

Первый запуск восстанавливает проверяемый демонстрационный архив в **пустые именованные тома** `state` и `shared`; обучение и внешние сайты для запуска не требуются. Повторные запуски используют сохранённое состояние. Данные, модели, задания и сценарии переживают `docker compose -f compose.single.yaml restart`. `docker compose -f compose.single.yaml down` сохраняет тома; ключ `-v` удаляет их и не нужен для обновления.

**Один контейнер, общий лимит 4 vCPU / 4 ГиБ RAM, swap запрещён** (`mem_limit = memswap_limit`). Внутри работают API, worker импорта/экспорта и worker моделей; модель использует до двух потоков. При завершении любого процесса контейнер перезапускается, очередь и данные сохраняются в томах. Альтернативная схема с тремя раздельными контейнерами сохранена в `compose.yaml`; её лимиты не относятся к одноконтейнерным измерениям. Встроенный комплект содержит реальные labels января–октября 2025, промежуточные версии без маршрута № 17 и без сентября, готовые сезонную модель, полный сервисный LGB/CB/RF, новый погодный ансамбль 144/96/64 и годовой сценарный адаптер. Также включены почасовые температура/влажность/осадки 2024–2025 и реальные ДТП Москвы 2025. Исходные 9,7 ГБ транзакций для запуска не нужны.

Архив разделён на части ≤64 МиБ в `deliverables/platform-demo.tar.gz.part-*`; контрольные суммы — [manifest](deliverables/platform-demo.manifest.json). Docker собирает их автоматически. Для ручного восстановления:

```bash
cat deliverables/platform-demo.tar.gz.part-* > /tmp/potok-demo.tar.gz
backend/.venv/bin/moscowt --state-dir /tmp/potok-state --data-root /tmp/potok-data restore /tmp/potok-demo.tar.gz
```

## Работа с приложением

Боковая навигация разделяет **«Данные и модели»** и **«Сценарии»**. Сверху — только **«Экспорт»**. Периоды импорта, обучения, выпуска и выгрузки независимы; задания выполняются на сервере и переживают обновление страницы.

1. В «Наборах данных» создайте самостоятельную историю либо дополните/исправьте выбранную редакцию. Редакция — сохранённое неизменяемое состояние набора. Повтор не удваивает суммы; неизвестные наблюдения остаются пропусками. Название, период, маршруты, источник и полнота видны рядом с выбором.
2. В «Моделях и обучении» выберите редакцию/период/алгоритм, обучите модель или проверьте и загрузите переносимый ZIP. Поддержана локальная конвертация доверенных joblib/pickle сервиса. Веса ансамбля 70/10/20% редактируются отдельно: новая модель и пересчёт выбранного выпуска без обучения деревьев.
3. В календаре карты можно выбрать даты до **31.10.2026** включительно: годовой сценарий считается на 12 месяцев от выпуска **01.11.2025**, а не от текущей даты компьютера. Выбор будущей даты подключает готовый годовой выпуск только для вашего просмотра; общая публикация сохраняется. В статистике маршрутов доступны все линии, переключатель исторического среднего и кнопка «Развернуть график». Для следующего периода подготовьте новый день/месяц либо годовой сценарий и отдельно опубликуйте выпуск. Смена полей формы сама не переключает карту. Новый маршрут требует истории и обучения; отдельного правила обнуления № 5 нет.
4. Откройте «Сценарии»: в чистой поставке уже выбран ансамбль с почасовой погодой. Задайте маршрут 17, 1 ноября 2025, 08:00–10:00. Сначала рассчитайте нейтральную базу. Затем измените погоду, сезонную поправку или расписание, добавьте ДТП на карте и снова нажмите «Рассчитать сценарий».
5. Например, исходный интервал 10 минут → 8 минут при ε=0,3 даёт множитель спроса около 1,0692. ДТП 08:30, 60 минут, ограничение 50% дополнительно меняет доступность. Это редактируемые допущения; погодные значения проходят через реальные деревья модели. Черновик сохраняется, прежний результат после правок отмечается устаревшим.
6. Карта, сравнение и CSV/Parquet читают один завершённый результат. Полный архив переносит данные, модели и завершённые сценарии. Конкурсный профиль — отдельный исходный шаблон на 14 640 ключей, без сценариев.

[Подробная демонстрация, формулы, импорт моделей и ограничения](docs/SCENARIOS.md).

Форматы и HTTP-примеры: [API](frontend/API.md), [данные и архитектура](backend/README.md), [маршрутная геометрия CSV](docs/ROUTE_CSV.md).

## Модели и фактическая проверка

Сервисный ансамбль: веса CatBoost/LightGBM/RandomForest **0,7/0,1/0,2**, по умолчанию 1378/332/300 деревьев. Его признаки строятся из истории до фиксированного origin; он отделён от неизменённого конкурсного исходника. Сезонная модель использует недельный профиль последних восьми недель. Требуется минимум 21 день для сезонной модели и 56 дней для ансамбля/годового адаптера, а также три известных наблюдения каждого дня недели и часа. При недостатке истории сервис возвращает причину отказа.

Новый демонстрационный погодный ансамбль проверен отдельно в [отчёте факторов](docs/scenario-factor-evaluation.json). Следующие результаты относятся к **прежним полным сервисным рецептам**, а не к новой демонстрационной модели. Они проверены на фиксированных выпусках 01.09 и 01.10.2025. WAPE (меньше — лучше):

| Модель | День 01.09 | Сентябрь, почасово | День 01.10 | Октябрь, почасово |
|---|---:|---:|---:|---:|
| Сезонная | 0,21290 | 0,21813 | 0,17293 | 0,14033 |
| LGB/CB/RF | 0,13578 | 0,15755 | 0,12750 | 0,09553 |

[Машинный отчёт](docs/model-validation.json) также содержит MAE, смещение, маршрутные результаты и ошибки суточных/месячных сумм. Эти периоды уже использовались в исследованиях: **независимым holdout их не называем**. Для независимой проверки нужны новые факты. У № 5 нет положительной истории в исходных labels; перенос на него не валидирован, WAPE при нулевой целевой сумме не определена. Это отражено в паспортах моделей.

Исходный конкурсный LGB/CB/RF выполнен отдельно в Docker: 102,69 с, пик RSS 1,19 ГБ. Ключи CSV совпали с предоставленным эталоном, но значения различаются в 12 038 строках из 14 640. Совпадение числового результата **не достигнуто**; исходное окружение автора неизвестно, причина расхождения не установлена. [Воспроизведение и команды](models/lgb_cb_rf/README.md), [сравнение](docs/ensemble-reproduction.json).

## Источники и ограничения

[Реестр источников и доказательства эффекта](docs/EXTERNAL_SOURCES.md) содержит ссылки, способы получения, покрытие и правила доступности до origin. Бесплатный оперативный Open-Meteo скачивается отдельным заданием по запросу пользователя; в inference нет сетевых вызовов. Время получения сохранено, выдавать hindcast за доступный в прошлом прогноз нельзя.

Новое сравнение одинаковых ансамблей 144/96/64 на июне, сентябре и октябре 2025: календарь уменьшил среднюю WAPE на **1,832 процентного пункта**, погода ухудшила на **0,129 п.п.**, ДТП — на **0,055 п.п.** Эффект погоды/ДТП в оперативном режиме не подтверждён. Ретроспектива с фактическими условиями окна показана отдельно и не выдаётся за оперативное качество. [WAPE, MAE, смещение, маршруты и разброс](docs/FACTOR_RESULTS.md).

[Датасет ДТП Москвы 2025](dataset/derived/moscow_accidents_2025/README.md): **8 354 события**, все 12 месяцев, исходный ZIP/CSV/Parquet/manifest. Источник — [Карта ДТП](https://dtp-stat.ru/opendata/), возможная близость к датированным трассам — 100 м. Время публикации/длительность перекрытия неизвестны; пользовательские ДТП не добавляются в обучение. Пригодный открытый архив дорожных скоростей не подтверждён. Максимальный балл за внешние источники не заявляется.

Расписание сентября 2026 охватывает девять маршрутов, не содержит выходов и вагонов. Его импорт строит оценку одновременных рейсов и отмечает неполноту. Перенос на 2025 год доступен только с явным флагом сценария. Полные назначения вагонов импортируются отдельным форматом; пересечения одного физического вагона объединяются, межмаршрутные конфликты не превращаются в достоверный выпуск. Интенсивность — **сумма валидаций / сумма вагоно-часов**, шкала **5 / 20 / 34 / 50**. [Методика участков](docs/SECTION_MODEL.md).

Годовой адаптер не обучает годовую сезонность на неполном годе. Погода долгих горизонтов — климатологический сценарий; ручные множители не доказывают причинный эффект. Диапазоны сценариев не являются доверительными интервалами. Для оценки переполнения нужны вместимость, посадки и высадки; для подтверждения остановочных прогнозов — наблюдения по остановкам/GPS.

## Проверки и производительность

[Таблица критериев и приёмка](docs/IMPLEMENTATION_STATUS.md), [протокол проверок](docs/VALIDATION.md), [нагрузка и команды](docs/PERFORMANCE.md). Пройдены 90 backend-тестов, 6 проверок исходной географии, 23 frontend-теста и 22 браузерных сценария, включая публикацию CSV-геометрии на изолированной поставке.

**Фактическая производительность: один контейнер, 4 vCPU / 4 ГиБ RAM, swap запрещён.** Замеры 27.09.2026 на AMD Ryzen 5 7500F, Linux, Docker; генератор на том же хосте, loopback. API и оба worker включены в эти общие лимиты.

| Нагрузка | Фактические RPS | p95 / p99, мс | CPU среднее / максимум от 4 vCPU | RAM (working set), МиБ | Ошибки чтения |
|---|---:|---:|---:|---:|---:|
| 300 RPS + поток событий + CSV, 60 с | 300.00 | 4.20 / 31.58 | 26.5% / 34.3% | 370–506 | 0 |
| 600 RPS + поток событий + CSV, 60 с | 599.99 | 51.52 / 105.96 | 34.5% / 46.9% | 433–523 | 0 |
| 300 RPS во время обучения + CSV, 30 с | 300.01 | 4.60 / 12.27 | 57.5% / 78.5% | 735–958 | 0 |

**Swap — 0, OOM — 0; RAM после прогрева колеблется в указанных пределах.** При 300 RPS параллельно полностью обработано 270 000 сырых событий валидации (4355 событий/с); при 600 RPS — 260 000 (4270 событий/с). Это HTTP-пакеты по 10 000 событий с нормализацией и сохранением в независимый набор. Суммы проверены, основной выпуск неизменен; все CSV-задания завершились.

RPS/p95 относятся к прогретой смеси готовых запросов карты, динамики, сравнения, тепловой матрицы, маршрутов и capabilities. CPU приведён относительно выделенных четырёх vCPU; значение ниже 60–80% означает дополнительный запас. Длительность опытов 60/60/30 с, многосуточная стабильность и предельный RPS не измерены. Погодный сценарий рассчитан за **7.92 с**, годовая агрегация — p95 **708 мс**; это отдельные тяжёлые операции.


SQLite и файловые блокировки рассчитаны на один хост, один API и по одному worker каждого канала. Горизонтальное масштабирование нескольких хостов не проверено. Нет пользовательской авторизации: порт по умолчанию привязан к localhost. Тайлы карты требуют сеть, но их недоступность не блокирует локальную геометрию, числа и экспорт. [Архив P0](docs/archive/) сохранён как история, его показатели не относятся к текущей поставке.
