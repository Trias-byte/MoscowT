# Сценарии

Сценарий сохраняет параметры отдельно от базового прогноза. После изменения формы нужно запустить расчёт; до его завершения показан прежний результат с отметкой об устаревании.

1. Откройте раздел «Сценарии» и выберите готовый выпуск, маршруты и период.
2. Рассчитайте нейтральную базу для сравнения.
3. Измените доступные факторы: погоду, сезонный коэффициент, интервалы/время движения или ДТП.
4. Запустите расчёт и дождитесь завершения задания.
5. Откройте результат на карте или выгрузите его. CSV и Parquet используют тот же сохранённый расчёт.

## Факторы

Погода применяется к модели с соответствующими признаками. Для будущих дат используется доступный прогноз либо климатологический профиль. Ретроспективные фактические условия имеют диагностический режим и не выдаются за известные на дату выпуска.

Сезонная поправка — заданный пользователем множитель. Изменение частоты движения преобразуется в коэффициент спроса через эластичность. Ограничения движения учитываются по времени пересечения с часом и рабочим интервалом; несколько ограничений не должны повторно считать один и тот же недоступный интервал.

ДТП задаёт место, начало, длительность, долю ограничения и затронутые маршруты. Близость исторического ДТП к маршруту сама по себе не доказывает перекрытие. Пользовательские события не добавляются в обучающие наблюдения.

## Периоды и отображение

Периоды задаются в московском времени, начало включено, конец исключён. Почасовой экспорт требует границ полного часа. Период сценария не изменяет автоматически периоды импорта, обучения или другого экспорта.

Выбор будущего выпуска для просмотра не равен общей публикации. Неизвестные наблюдения остаются пропусками. Число валидаций на маршруте не суммируется по участкам: одна поездка может проходить несколько участков.

Для технического контракта используйте `/docs`: схемы `ScenarioSpec`, `ForecastSpec` и `PeriodExportSpec` формируются из текущего кода.
