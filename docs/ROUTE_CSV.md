# Загрузка маршрута из CSV

В шапке приложения нажмите **«Загрузить маршрут»**. В диалоге можно скачать пустой шаблон или выбранный маршрут вместе со всеми точками трассы. Измените файл, выберите его, проверьте номер, направления, даты и количество остановок, затем нажмите **«Добавить маршрут на карту»**.

Импорт геометрии отделён от экспорта пассажиропотока. Загруженные трассы помечаются как пользовательские; они не изменяют факты, прогнозы и итоговые суммы.

## Формат

UTF-8 с необязательным BOM, разделитель `;` или `,`, десятичная точка. Порядок столбцов фиксирован:

```csv
route_id;route_name;direction;valid_from;valid_to;point_order;longitude;latitude;stop_id;stop_name
```

| Столбец | Содержание |
|---|---|
| route_id | Один номер на файл, до 16 букв, цифр, дефисов или подчёркиваний |
| route_name | Название маршрута, до 160 символов |
| direction | 0 или 1; каждый код заменяет только соответствующее направление |
| valid_from | Первый день действия включительно, YYYY-MM-DD |
| valid_to | Первый день без этой версии, YYYY-MM-DD |
| point_order | Порядок точек внутри направления от 1, без повторов и пропусков |
| longitude, latitude | Долгота и широта WGS84 |
| stop_id, stop_name | Код и название остановки; оба пустые у промежуточной точки |

Один файл содержит один маршрут и один общий период. Для всего года: `2025-01-01` — `2026-01-01`. Первую и последнюю точки каждого направления нужно обозначить остановками. Включайте все промежуточные точки пути, чтобы линия повторяла трассу. Разрывы между соседними точками более 1 км отклоняются. Координаты должны находиться в области Москвы (37.25–37.95 E, 55.45–55.95 N). Ограничения: 5 МБ, 20 000 точек.

У существующего номера новая версия имеет приоритет только в указанных направлениях и днях. При пересечении с предыдущим CSV диалог перечисляет затрагиваемые файлы; последняя применённая загрузка имеет приоритет. Вне периода действует предыдущая версия. Новый номер виден в разделе «Загруженные маршруты» и на справочном слое карты. Числовых данных для него нет.

## API и хранение

- `GET /api/v1/network?snapshotId=…&date=2025-07-01` выбирает геометрию дня; дата — московская календарная.
- `POST /api/v1/geometry` принимает обычный `Scope` с дополнительным `geometry.date`; это позволяет менять трассу активного кадра, не пересчитывая числовые ряды периода.
- `POST /api/v1/route-imports/preview`: JSON `{snapshotId, filename, csv}`. Возвращает проверенный состав, даты и предупреждения. Сохраняет подготовленный артефакт, но не изменяет текущую сеть.
- `POST /api/v1/route-imports/{id}/apply`: JSON `{snapshotId}`. Публикует новый неизменяемый снимок. Повторное применение того же файла идемпотентно. Если другая загрузка изменила сеть после открытия диалога, возвращается 409.

CSV хранится как проверенная геометрия в `artifacts/route_imports/`; новые версии сети — в `artifacts/networks/`. Старые снимки доступны по прежним идентификаторам. Данные истории, модель и прогноз сохраняют свои идентификаторы. При повторной подготовке того же базового архива уже применённые CSV сохраняются.
