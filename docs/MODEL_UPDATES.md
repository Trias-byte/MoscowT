# Обновление модели

Импорт истории создаёт новую редакцию данных. Для продолжения рабочего набора интерфейс предлагает обновить базовый прогноз. Операция запускается фоновым заданием `model_refresh` и сохраняет контрольные точки.

`ModelRefresh` проверяет связь новой редакции с рабочей историей, определяет полный доступный период, обучает модель того же семейства и сравнивает её с базой на доступных временных окнах. Публикация выполняется после проверки качества. При отказе или ошибке действующая публикация сохраняется; результат и причина доступны в задании.

Неполные последние сутки не включаются в обучение конкурсной базы. Горизонт этой модели остаётся равным 61 дню. Для года используется отдельный адаптер. Новый маршрут требует достаточной истории; модель не придумывает данные за отсутствующие часы.

## Работа в интерфейсе

1. В «Данных и моделях» выберите рабочую редакцию и загрузите новые наблюдения.
2. Проверьте предварительный отчёт: период, маршруты, повторы и конфликты.
3. Примените импорт с обновлением прогноза либо запустите обновление из карточки редакции.
4. Дождитесь завершения задания; изучите новый выпуск и результат проверки качества.

Переход между страницами и перезапуск браузера не отменяют серверное задание. Отмена и прерывание процесса обрабатываются очередью; завершённые этапы обновления хранятся в контрольных точках.

Проверки поведения: `backend/tests/test_model_refresh.py` и `frontend/tests/e2e/model-refresh.spec.ts`. Входной HTTP-контракт доступен в `/docs`.
