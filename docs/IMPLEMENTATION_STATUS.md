## Состояние обязательной приёмки

- Повторный импорт не меняет сумму, исправление создаёт новую версию, пропуск не равен нулю — автоматические тесты и реальный HTTP-цикл.
- Будущие target, недоступные события и будущая погода не меняют признаки старого origin — тесты. Для оперативной погоды отдельно проверены дата получения и покрытие.
- Сезонный baseline и LGB/CB/RF сохраняются/загружаются; модель обучает новый строковый маршрут и № 5 с реальной положительной историей без условных ветвей по номеру.
- День и месяц проверены на фиксированных сентябрьском/октябрьском выпусках полных рецептов. Год помечен как невалидированный сценарий; месячная сумма равна сумме часов.
- Ночные интервалы, частичные часы, совпадения бортовых номеров с ведущими нулями, повторные назначения, смена служебной даты и межмаршрутный конфликт проверены.
- Пространственный сервис сохраняет остановочную сумму. API участков и экспорт используют один расчёт знаменателя, включая дополнительный бюджет по направлениям.
- Задания имеют lease/владельца/идемпотентность; отмена и падение процесса не переключают активный выпуск и не публикуют частичную модель. [Проверка восстановления](worker-recovery.json).
- Чистый Compose восстанавливает готовую поставку без сети и обучения на старте. Через HTTP выполнены импорт сентября, добавление № 17, обучение обеих моделей, три горизонта, сценарий, CSV и Parquet.
- Исходный ансамбль выполнен отдельно в Docker. Числовое совпадение с предоставленным CSV **не достигнуто**; [расхождение](ensemble-reproduction.json) сохранено явно.

## Ревизия и очистка

| Блок | Решение |
|---|---|
| Данные | Один канонический репозиторий, immutable исходники/месячные разделы; IDs вместо копирования таблиц в v1 |
| Модели | Общий контракт и сервис публикации; конкурсный исходник изолирован; RF inference детерминирован, версия кода записана в выпуск |
| API/агрегация | v1 и v2 разделяют один сервис числовых представлений и кэш; формулы сценариев и интенсивности вынесены из UI |
| Расписания | Один импортёр с двумя явными методами, объединение интервалов физического ресурса; неизвестное покрытие не становится нулём |
| География | История OSM и пользовательский CSV сохранены; OD-профили кэшируются; frontend-реализация оставлена только для VITE_DEMO и контрольных тестов |
| Очереди | Новая очередь использует соединение существующего репозитория по композиции; старый протокол остаётся только для совместимости карты |
| UI | Сворачиваемая панель с независимыми периодами, устойчивые задания, проверяемые Zod-ответы, явные ошибки и ограничения |
| Поставка | API/general worker/model-worker, постоянные тома и лимиты, готовые три модели; демонстрационный архив не включает промежуточные research-модели |
| Репозиторий | Удалены неиспользуемый `ForecastExpert`, мёртвая функция агрегации, устаревший `NEXT_MODEL_PROMPT.txt`, машинный `.inspect.ndjson`, дублирующий полный demo tar; `.gitignore` сокращён до реально используемого стека |
| Исторические материалы | HANDOFF/inventory/P0-проверки сохранены в `docs/archive`; полезная книга связей маршрутов перенесена из outputs в `deliverables/references` |

Рабочие данные, исследовательские модели и ранее опубликованные версии не удалялись. «Проще» здесь означает уменьшение дублирования и явные границы, а не превращение каждой математической функции в класс. Оптимальность всех возможных конфигураций не заявляется: измеренная область нагрузки описана отдельно.

## Что остаётся внешним ограничением

Новые независимые факты; подтверждённый почасовой трафик за нужный период; GPS/остановочные наблюдения, вместимость и высадки; школьный календарь; архив реальных погодных выпусков до исторического origin. Без них нельзя честно доказать независимое качество, фактическую остановочную точность, переполненность, годовую сезонность либо четыре положительных эффекта источников. Эти ограничения не скрыты в интерфейсе или отчётах.
