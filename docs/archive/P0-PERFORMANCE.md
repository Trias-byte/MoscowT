# Нагрузочная проверка P0

Измерено 25 сентября 2026 года. Цель **300 RPS, p95 ≤ 250 мс** достигнута в обоих описанных сценариях при параллельном экспорте. Каждый прогон — 9 000 запросов за 30 секунд. Ошибок HTTP или транспорта в итоговых прогонах нет.

| Кэш | RPS | p50, мс | p95, мс | p99, мс | Ошибки | CPU, средний / пик | Пик памяти |
|---|---:|---:|---:|---:|---:|---:|---:|
| Прогретый | 299.99 | 3.21 | 4.57 | 6.58 | 0 | 70.9 / 81.9% | 218.9 МиБ |
| Холодный | 299.99 | 4.67 | 148.32 | 262.35 | 0 | 87.7 / 104.4% | 220.7 МиБ |

CPU приведён в шкале Docker: 100% — одно логическое ядро, доступно 200%. Память и CPU включают API и отдельный worker. Ресурсы снимались `docker stats`, поэтому это максимумы выборки, а не непрерывное измерение каждого пика.

## Условия

- Docker Compose: один контейнер, `NanoCpus=2000000000`, `Memory=2147483648`, один процесс API и один worker экспорта. Четыре потока обработчиков API; числовые расчёты представлений ограничены общей блокировкой кэша.
- Хост: AMD Ryzen 5 7640HS, 12 логических CPU, около 14,8 ГиБ RAM, NVMe KIOXIA KBG50ZNV512G. Linux, Docker 29.8.1. Это рабочая машина с другими запущенными контейнерами, не выделенный стенд.
- Python 3.12, зависимости из `backend/uv.lock`; генератор aiohttp работает на хосте вне лимитов контейнера. Адрес `127.0.0.1:8081`, без TLS и сжатия.
- Фиксированный snapshot `snapshot-a8c0de3fc04710e998d35944`, история 72 960 ключей, прогноз 14 640 ключей. Кэш: 64 числовых представления и 64 МиБ консервативного бюджета; до трёх матриц в памяти.
- Заданный поток — open loop, 300 запросов/с, до 96 активных клиентских запросов. В задержку включены ожидание своей очереди и отклонение фактического запуска от расписания. После 30 секунд генератор дожидается ответов; RPS считается по полному времени завершения.

## Смесь запросов

`map-snapshot`, `timeseries`, `route-comparison`, `heatmap` — по 20%; `capabilities` и `routes` — по 10%. У числовых запросов три маршрута в двух третях вариантов и десять в остальных. Параллельно создаются шесть CSV-заданий: первое примерно через секунду, последующие раз в пять секунд. Все 12 заданий обоих прогонов завершились `ready`.

**Прогретый кэш:** 24 заранее рассчитанные области прогноза. Обычно день с часовым шагом; каждый пятый вариант — до семи дней с суточным шагом. Ответы от 903 до 59 003 байт, средний размер 7 535,7 байта.

**Холодный кэш:** процесс контейнера перезапущен, матрица истории до прогона не загружена. 600 различных областей истории с часовым шагом за сутки вытесняют друг друга из кэша на 64 записи. Ответы от 903 до 62 143 байт, средний размер 8 596,1 байта. Дисковый кэш Linux намеренно не сбрасывался: «холодный» здесь относится к кэшу приложения и загрузке Parquet после старта процесса.

При настройке устранены повторные мелкие операции NumPy и конкуренция большого числа потоков. Предварительный генератор на HTTPX сам насыщал ядро при накоплении запросов; итоговые результаты получены aiohttp с ограниченной активной очередью. Полные данные этих прогонов сохранены в [performance-warm.json](performance-warm.json) и [performance-cold.json](performance-cold.json).

## Воспроизведение

Запустить подготовленный контейнер и выполнять прогоны последовательно, без сборки/обучения/браузерных тестов в фоне:

```bash
docker compose restart app
# Дождаться HTTP 200 от http://127.0.0.1:8081/health/ready
uv run --directory backend python scripts/load_test.py \
  --url http://127.0.0.1:8081 --container moscowt-app-1 \
  --mode cold --rps 300 --seconds 30 --exports \
  --output ../docs/performance-cold.json
uv run --directory backend python scripts/load_test.py \
  --url http://127.0.0.1:8081 --container moscowt-app-1 \
  --mode warm --rps 300 --seconds 30 --exports \
  --output ../docs/performance-warm.json
```

Короткий замер не доказывает устойчивость под длительной нагрузкой. В него не входят обучение, первый скачиваемый frontend-бандл, внешние тайлы, доставка больших CSV и произвольные максимальные интервалы API. Размер и сложность выбранных областей влияют на задержку. Показатель p99 холодного сценария может превышать 250 мс; условие приёмки задано для p95.
